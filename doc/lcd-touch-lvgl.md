# LCD + GT911 + LVGL 交互例程

## 启用和功能

`src/lcd-touch-lvgl.c` 使用已有 LVGL v8.3.11 和 ST7282 RGB565 显示配置，接入 GT911 单指指针输入。仅保留 `INIT_APP_EXPORT(lcd_touch_lvgl_start)`，注释其他例程的 `INIT_APP_EXPORT(...)`，重新编译、烧录、复位。

- RED/GREEN/BLUE：切换左侧预览颜色，统计颜色按钮点击次数。
- 开关：切换预览启用状态，显示 ENABLED/DISABLED，禁用时色块显示 OFF。
- 滑块：范围 0～100，拖动时实时更新滑块和数值；松手后更新左侧色块明暗。数值仅用于界面测试，不控制背光或外设。
- RESET：恢复蓝色、启用状态、50% 和颜色点击计数 0；触摸帧数和错误计数继续累计。
- 状态行：显示 UP/DOWN/WAIT、X/Y、触点数 N 和主触点 ID；底部显示点击、有效触摸帧和错误计数。

GT911 使用 I2C1、RST=P801、INT=P004。地址 0x5D/0x14 自动探测，校验产品 ID 和 480 × 272 坐标范围。LVGL 的输入定时器轮询 ready 寄存器，无独立触摸线程或 IRQ 回调；读取后清除状态。坐标直接对应屏幕，不旋转、不交换 X/Y。

多指时固定跟踪本次最先选中的触点，其他触点只计数，不同时操作多个控件。主触点先抬起、其他手指仍按下时显示 WAIT，等待全部松开再允许下一次操作。输入异常时取消当前操作并等待释放，避免旧坐标触发误点击。

## 滑块不跟手问题与修复

2026-10-01 首轮验收反馈：“其他的都是正常的。唯独滑块不太跟手。”此时未提交，继续修复。

同一 GUI 线程既读触摸又绘制。原版每次滑块变化都刷新三个颜色按钮、开关文字和透明大色块，绘制期间无法及时读取下一帧触摸。板上测量原版 I2C 读取最大仅 2 ms，而 51 步滑块扫描的更新加绘制累计 5230 ms，单次最大 103 ms，主要瓶颈为重绘。

最终处理：

1. 拖动只更新滑块和数值，将大色块明暗更新放在松手后；颜色按钮、开关等仅在相关事件发生时更新。
2. 预先计算色块颜色，用不透明矩形填充，避免逐像素透明混合和圆角遮罩开销。
3. 触摸读取间隔 20→8 ms，显示刷新定时器 30→16 ms，GUI 主循环等待 5→1 ms；诊断文本每 200 ms 检查且只在内容变化时更新。

| 版本 | 51 步更新和绘制累计 | 单步最大 |
| --- | --- | --- |
| 原版 | 5230 ms | 103 ms |
| 减少无关重绘并使用不透明填充 | 2226 ms | 44 ms |
| 最终拖动路径只更新滑块和数值 | 1348 ms | 27 ms |

这些数据为程序更新和绘制耗时，不是手指到屏幕的端到端延迟；16 ms 刷新定时器不代表实测达到 60 FPS。单帧缓冲直接更新，未做垂直同步交换。最终用户复验确认“跟手正常，验收通过”。

## 构建与诊断

```powershell
python scripts/build_flash.py --build-only
python scripts/build_flash.py
python scripts/monitor_msh.py --port COM8
```

串口为 115200、8N1。MSH `touch_lvgl_status` 显示输入、控件状态和耗时峰值；`list thread` / `free` 查看栈和堆。`read_max` 是整个输入读取回调耗时；`render_max` 包含启动时全屏绘制，不能当作滑块单步耗时。

`touch_lvgl_bench` 在线程内执行 0～100 的 51 步自动扫描，每步设置数值、触发变化事件并同步绘制，测量这些工作的耗时（不计每步额外 16 ms 等待）；结束后恢复原数值及预览。测试期间短暂自动操作界面并暂停正常输入处理，请先松开屏幕，测试完成后再操作。此命令用于渲染回归，不能代替真实触摸验收。
