# CPU直读SSI FIFO录音对照

日期：2026-10-07。用户在正常距离持续说话，audio-record导出的MP3仍只有沙沙声。2～3cm不作为验收前提。本对照保留官方麦克风时钟与SSI格式，绕过自写连续录音的DTC、RT-Thread队列、板端滤波和降采样，检查去掉这些环节后能否录到人声。

这是基于官方配置/API的临时诊断，尚无官方完整U9录音应用可直接复现。官方源码查证与mic-record-03数据见 [audio-official-review.md](audio-official-review.md)。它不属于生产MSH测试，不增加hmi_test命令，也不修改src/hal_entry.c。

## 用户操作

保持板载调试USB连接。关闭Studio调试会话和其他占用SWD探针的工具，在工程根目录执行：

```powershell
python scripts/audio_fifo_to_mp3.py --run --output logs/mic-fifo-01
```

看到“即将采集”后，按正常距离持续说“一二三四五，麦克风测试”。前约3秒用于预热，后5秒保存。看到“采集完成，可以停止说话”后停止，等待SWD导出和音频转换。脚本不打开COM8，不自动播放音频；结束会复位板卡，临时测试前不要同时运行其他例程。

打开logs/mic-fifo-01.mp3，反馈是否能辨认自己的话，还是只有噪声/静音。原样PCM16为.wav，未加试听增益的MP3为.raw.mp3，试听PCM16为.listen.wav，统计为.json。原始报告、两段PCM、Flash核验及复位日志保存在logs/mic-fifo-01.swd目录。再次测试使用02等新编号，旧前缀会被拒绝，避免覆盖录音。

## 数据路径

```text
U9 -> SSI FIFO -> CPU成对读取左右字 -> 左PCM24显式符号扩展
   -> 固定除以256转PCM16 -> 全速保存5秒 -> SWD导出 -> 电脑WAV/MP3
```

GPT1周期39、占空计数19，SSI为官方PCM24/32位时隙/主机模式/WS_CONTINUE_OFF。计算采样率48076.923Hz，WAV标记48077Hz。预热144231帧约3秒，保存240384帧、480768字节，约5秒。右声道记录峰值用于核对声道；L/R接地的U9应输出左声道。

CPU中断保持屏蔽，SSI接收配置取消DTC子驱动。启动接收后直接轮询FIFO，成对读取左右字，不再调用依赖应用RAM的驱动或内核。检查SSI溢出及10秒超时；主机验证初始化返回值、完整帧数、完成标志、SSISR及4.99～5.01秒时长，失败则保留诊断日志，不生成试听音频。

固定除以256是24位到16位的幅度换算，没有按声音自动调增益。电脑试听版本只去整段均值并施加一次固定增益，噪声也会放大；同时保留未经电脑处理的WAV。没有滤波、降采样、降噪或板端喇叭回放。MP3使用48kHz/128kbit/s单声道，有损编码不作为原始数据证据。

## 临时RAM与恢复

使用scripts/diagnostics/audio-fifo.c单文件。scripts/audio_fifo_to_mp3.py先构建临时ELF，再通过SWD运行。仅构建可用：

```powershell
python scripts/audio_fifo_to_mp3.py --build-only
```

本机需要既有Studio ARM GCC/PyOCD、pyelftools和FFmpeg；不会自动安装。pyelftools复用logs/oled-validation/python目录。Flash函数/配置地址从当前Debug/rtthread.elf解析，启动前逐字核验已烧录Flash中的对应函数与配置，拒绝不匹配的固件。

芯片链接配置为RAM_START=0x1FFE0000、RAM_LENGTH=0xA0000，结束地址为0x20080000。临时内存安排如下：

| 区域 | 起点 | 结束地址（不含） | 内容 |
| --- | --- | --- | --- |
| PCM第一段 | 0x20000000 | 0x20064000 | 前204800样本 |
| 栈保留 | 0x20064000 | 0x20065000 | MSP，必须匹配BSP实际边界 |
| PCM第二段 | 0x20065000 | 0x20076600 | 后35584样本 |
| 代码 | 0x20078000 | 按ELF实际长度 | 临时采集循环 |
| 报告/数据 | 0x2007A000 | 按ELF实际长度 | 24字诊断报告 |

主机严格检查ELF装载段不覆盖PCM/栈、不超出SRAM。录音会覆盖原应用控制对象，结束直接停SSI/GPT，主机通过finally复位并恢复运行原Flash固件，不调用被覆盖对象的Close。若探针中途断连导致复位失败，日志会报错；重新连接后复位板卡即可恢复，Flash没有改写。

## 实物流程验证及边界

首次试运行时临时地址误设为0x20080000，加载器拒绝加载，CPU进入HardFault，完成报告不成立；脚本拒绝生成音频并复位恢复。已把代码/数据移入真实SRAM范围，并增加装载失败文本检查及装载段范围检查。该次失败属于诊断工具错误，不支持任何麦克风结论。

修正后mic-fifo-flow-03完成384615源帧（预热+保存）、240384保存样本，DWT时长4.999967秒，SSI状态0、右声道峰值0；原样WAV/MP3生成，CRC32=FDC90859，复位日志确认原固件恢复。没有安排用户同步说话，因此只验证流程；当前人声验收仍未通过。

最终分离采集/导出提示后，mic-fifo-flow-04再次完成相同帧数和时长，SSI状态0、右峰值0，CRC32=E6FE4B1A，CFSR/HFSR=0。核对两段PCM长度为409600/71168字节，整个WAV数据区与两段拼接逐字节相同；已复位运行原固件。4项主机检查通过，覆盖不完整报告、HardFault完成标志缺失、初始化/溢出/帧数/时长异常的拒绝，以及DWT回绕、PCM有符号样本和48kHz WAV字节保真。仍未安排同步发声，不作为声学验收证据。

下一轮若能辨认人声，说明去掉DTC/队列/板端处理后录音可用，回查生产链路；若仍只有噪声，说明这些环节移除后现象仍在，继续检查SSI配置之前的数字与声学链路。两种结果都需要声音内容证据，完整计数、RMS或非零数据不能单独证明录到了人声，也不能单独认定U9损坏。
