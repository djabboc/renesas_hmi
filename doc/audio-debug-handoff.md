## 当前结论

## 最近一次完整录音

用户自行运行 `scripts/audio_record_to_mp3.py`，输出前缀为 `logs/mic-record-02`：

- 采集 288384/288384 帧、751/751 块，5998ms；前约 1 秒预热，后约 5 秒保存。
- read/overrun/early_idle/stop 均为 0，storage_clipped=0；处理最大 1512µs，低于约 7987µs 块间隔。
- 保存 40064 个单声道 PCM16 样本、80128 字节，标记采样率 8013Hz，时长约 4.9999 秒。
- CRC32=`8B437AD7`；WAV 数据与串口导出逐字节一致，试听 WAV 与脚本转换也逐字节一致。
- PCM16 min=-933、max=339、均值=-80.452、交流 RMS=169.229，电脑试听固定增益约 14.0755 倍。
- 用户确认“持续说话，只有噪音沙沙”。本轮语音验收失败。

板端处理为 PCM24 左声道 → 127 点 3kHz 低通 → 六抽一 → 固定除以 32 → PCM16。没有高通、mu-law、自动增益或板端播放。MP3 由电脑 FFmpeg 编码；试听版本去整段均值并施加一次固定增益，噪声也会被放大。这里的 `.wav` 是板端处理后的 PCM16，不是未经处理的 SSI PCM24。

完整文件位于本机 `logs/mic-record-02.serial.txt/.json/.wav/.listen.wav/.raw.mp3/.mp3`。日志和录音属于本机忽略目录，未提交到 Git。详细控制日志见 [audio-record.md](audio-record.md)。

## 最新数字诊断的范围

U9 型号 MSM261S3526Z0CM；SCK=P403、WS=P404、SD=P406，L/R 接地选择左声道。GPT1 周期 39，对应计算 BCLK 约 3.077MHz、每声道约 48.077kHz；SSI 为 PCM24、32 位时隙。

SWD 临时 SRAM 程序同时读取三根线的 GPIO 输入。最终使用与生产相同的 WS_CONTINUE_OFF，2000 点耗时 24008 个 CPU 周期，约 0.200067ms；完整 WS 半周期 104 点、每时隙 32 个 SCK。按 I²S 延迟 1 位解码后，10 个左声道与 FIFO 完全一致，右声道为零，SSISR=0。

这次诊断关闭 CPU 中断、以 CPU 排空 FIFO，不使用生产 DTC/线程，也未安排用户同步说话。它只能观察 MCU 引脚的数字电平，不能测供电电压、模拟电平裕量、焊接质量或声学响应。原厂完整时序资料尚未取得，不能将所有器件时序要求视为已核验。

方法、逐字表及位置图见 [audio-wire-check.md](audio-wire-check.md)，本机原始证据位于 `logs/audio-wire-check/`。其中临时程序依赖当前 ELF 的 Flash 函数地址，不能直接用于其他固件版本。每轮退出均复位，当前运行的是原 Flash 固件。
